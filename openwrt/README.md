# OpenWRT

## Strip config 
```
jq '.outbounds |= map(del(.settings, .streamSettings))' /etc/xray/config.json
```

## Tunnel test
`test-tunnel.sh` compares direct, every `proxy-*` outbound from `/etc/xray/config.json`
(each in a throwaway xray on `127.0.0.1:208xx`, the service is untouched) and the live
balancer (`mixed` on `:10808`). Takes ~1.5 min and pulls up to ~8 s of downloads per test.
```
scp -O openwrt/test-tunnel.sh root@192.168.1.1:/root/   # -O: no sftp-server on the router
ssh root@192.168.1.1 ./test-tunnel.sh            # progress on stderr, table on stdout
ssh root@192.168.1.1 ./test-tunnel.sh --json     # same data as JSON
```
- `EXIT IP`, `LOC/COLO`: from Cloudflare trace (IPv4)
- `YT NODE`: googlevideo cache node (`report_mapping`)
- `YT LAT`: median of 5× `youtube.com/generate_204` ± spread, `FAIL` = failed of 5
- `CF` / `G Mbit`: 8 s download from speed.cloudflare.com / dl.google.com; `http429` = Cloudflare rate-limited that exit IP (frequent runs)
- `balancer ->`: which tunnel shares the balancer's exit IP; `russia (direct)`: ya.ru latency + Selectel download

`XRAY_CONF` and `LIVE_PROXY` override the config path and balancer proxy.

## PAC for Proxy Switcher
`proxy.pac` is built by `geo.yaml` (`geo2pac.py`) from the same lists as the geo files:
geosite/geoip matches go `DIRECT`, everything else goes to `SOCKS5 127.0.0.1:9050`.
Change the proxy by editing `var PROXY` at the top of the file (or `-p` in the workflow).
```
python3 openwrt/geo2pac.py <dir with geosite-*.txt and geoip *.txt> -p "SOCKS5 127.0.0.1:9050" -o proxy.pac
```

### Tests
```
python3 openwrt/test_geo2pac.py [proxy.pac ...]   # needs node
node pac-chrome-test/run.js proxy.pac             # real Chromium, see pac-chrome-test/README.md
```
If Proxy Switcher still reports `ERR_PAC_SCRIPT_FAILED`, re-convert the PAC: the old script stays stored in the Inline editor. The first line of a good one is `/* Generated by ...`.

## Tunnel test
`test-tunnel.sh` runs on the router. It tests `direct` (the router's own traffic bypasses tproxy), every `proxy-*` outbound in
`/etc/xray/config.json` (each in a throwaway xray on `127.0.0.1:208xx`; the running service is not touched)
and `balancer` (the live `mixed` inbound `:10808`). Needs `curl`, `jq`, `xray`. Takes ~1.5 min; downloads stop after 8 s
each, so a run can use a few hundred MB on a fast link.
```
scp -O openwrt/test-tunnel.sh root@192.168.1.1:/root/   # -O: the router has no sftp-server
ssh root@192.168.1.1 ./test-tunnel.sh          # progress on stderr, table on stdout
ssh root@192.168.1.1 ./test-tunnel.sh --json   # same data as JSON
```
- `EXIT IP`, `LOC/COLO`: from `1.0.0.1/cdn-cgi/trace` (IPv4; `1.1.1.1` is routed direct)
- `YT NODE`: googlevideo cache from `redirector.googlevideo.com/report_mapping`
- `YT LAT`: median ± spread of 5× `youtube.com/generate_204`, `FAIL` = failed of 5
- `CF` / `G Mbit`: 8 s download from `speed.cloudflare.com/__down` / `dl.google.com` (Chrome .deb, a stand-in for YouTube)
- `balancer -> proxy-NN`: the tunnel whose exit IP matches the balancer's
- `russia (direct)`: `ya.ru` latency and a Selectel speedtest download, direct only
